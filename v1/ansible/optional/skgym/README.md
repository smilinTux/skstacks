# skgym

[openGym](https://github.com/DuarteSantos8/openGym) on the swarm: a
self-hosted gym and body-weight tracker (weekly routines, guided workouts,
sets, body weight, stats), installable as a PWA, passkey sign-in, synced
across a person's devices. Opt-in: nothing renders or changes for an
instance that never runs `deploy_skgym-<env>.yml`.

## Upstream, license and images

- **License.** openGym's code is AGPL-3.0-or-later (plus an app-store
  exception that does not concern us). The exercise stills and animations
  inside the `web` image are licensed by Gym visual to openGym for use
  within openGym only; they are not AGPL. This role therefore **references
  the upstream images and vendors nothing**: no openGym code or media is
  copied into this repository, and the framework does not rebuild or
  republish the images (a framework-built `web` image would redistribute
  the Gym visual media from our registry, which their notice does not
  allow). Running the unmodified upstream image as a network service meets
  AGPL section 13 (the app links to its upstream source). If an instance
  ever patches the code, it must offer its modified source to its users.
- **Images.** `ghcr.io/duartesantos8/opengym-api` and
  `ghcr.io/duartesantos8/opengym-web`, release `1.4.1`, multi-arch
  (amd64, arm64), pinned by digest; the play refuses an image without
  `@sha256:`. The api image is the upstream `default` target (no AI runtime
  inside; the opt-in `coach` target is not used).
- **No phone-home from the server.** Nothing on the server calls out by
  default. Browsers talk to their own push service (Web Push) once a user
  turns reminders on; the Android app checks GitHub releases for updates;
  the AI Coach, if an admin ever enables and connects it, sends workout data
  to the chosen model provider (it is off here unless `COACH_DISABLED:
  false`). Hevy import uses the user's own Hevy API key from their browser.

## Design

### Services

| Service | Image | Replicas | What |
|---|---|---|---|
| `api` | `opengym-api` | **1, always** | Node, no framework. Keeps the whole database in memory and in JSON files under `/data` (`db.json`, `state-<uid>.json`, `uploads/`, `audit.log`, `vapid.json`, `secret`). Two replicas on one data dir would each hold their own copy: the replica count is not a knob, and updates are `stop-first`. |
| `web` | `opengym-web` | `WEB_REPLICAS` (1) | nginx (uid 101) serving the built app on `:8080` and proxying `/api/` to `api:3000`, so app and API share one origin (passkeys are bound to it). Stateless. |
| `backup` | `opengym-api` (same digest, no extra pull) | 1 | `skgym-backup loop`: a tar.gz of `/data` every `BACKUP_FREQUENCY` seconds into `BACKUP_PATH`. `BACKUP_ENABLED: false` removes it. |

Traefik (skfenceha, or skfence) routes `https://<host>/` to `web:8080`
(service health check `/api/health`, which is the api's own health seen
through nginx). Networks: `skgym-<env>` (api, web, backup) and
`cloud-public-<env>` (web only: the api is never on the Traefik network).

### Placement and data

- `DATA_PATH` (default `/var/data/skgym-<env>/data`, NFS on a typical
  instance) is bind-mounted at `/data`. openGym writes every file to a temp
  name, fsyncs and renames it (atomic, durable), and its load is a few
  small writes per workout, so NFS is fine. The data dir is root `0700`
  (passkeys and the session secret live there).
- For local disk, set `DATA_PATH` (and `BACKUP_PATH`) outside `/var/data`
  and `DATA_NODE` to the node that holds it: `api` and `backup` get
  `node.hostname == <DATA_NODE>`, the play creates the directories there,
  and it refuses a local path without `DATA_NODE` (local data on a floating
  service is an empty instance after the next reschedule). Same rule as
  sksso/skhub/skpayment.
- `PLACEMENT_CONSTRAINTS` (api, backup) and `WEB_PLACEMENT_CONSTRAINTS`
  (web) both default to `["node.role == worker"]`.

### Secrets vs settings

The only secret is `SESSION_SECRET`, the key every session cookie is signed
with. openGym generates one into `/data/secret` on first boot when the file
is missing; this role writes the vault value there instead (root `0600`,
`no_log`), so the vault is the source of truth, a restore of the data dir is
not needed to keep sessions valid, and the deploy **fails loudly** when it is
missing or shorter than 32 characters. Changing it signs everyone out (and
makes Coach provider credentials stored in `coach.json` unreadable, if the
Coach was ever connected). Everything else (`skgym.env`, root `0600`) is a
plain setting with a default; VAPID keys for push are generated by the app
into `/data/vapid.json`.

### Sign-in, SSO and the first admin

openGym has its own accounts: passkeys (default) and optional name+password
(`PASSWORD_LOGIN`). It has **no OIDC/OAuth support**, so Authentik cannot be
its identity provider. What the framework offers instead:

- `SSO_MIDDLEWARE` (e.g. `authentik@file`): forward auth on the app shell.
  The router then splits in two: `Host && PathPrefix(/api/)` with
  `TRAEFIK_MIDDLEWARES` only, and `Host` (everything else) with
  `TRAEFIK_MIDDLEWARES` plus the SSO middleware. `/api/` must stay outside
  forward auth (upstream SELF_HOSTING.md): the phone app and its pairing
  preflights carry no SSO cookie, and openGym authenticates every API call
  itself. Users then sign in twice (Authentik, then their openGym passkey);
  the gain is that nobody without an Authentik account ever sees the app.
  Authentik needs a proxy provider in forward-auth mode for the skgym host.
- Without SSO, lock the instance down in the app itself: the first admin,
  then invite-only.

Bootstrap of the admin (openGym makes the FIRST profile on an empty
instance its admin when `FIRST_USER_ADMIN` is on, the default here):

1. Deploy with `INVITE_ONLY: false` (default). Before telling anyone the
   address, open it, create your own profile (passkey, or password if
   `PASSWORD_LOGIN: true`). It is the admin. To keep strangers out of that
   window, deploy the first time with `SSO_MIDDLEWARE` set or
   `TRAEFIK_MIDDLEWARES` including an IP allowlist.
2. Set `INVITE_ONLY: true` (and `ALLOW_GUEST: false` if guests should not
   see the app at all) and redeploy. New people now need an invite code from
   the admin dashboard (Settings, Admin).
3. More admins: their user ids in `ADMIN_UIDS`.

An invite-only instance with no profile cannot get a first user (openGym
refuses every signup without a code, and nobody can make a code): always do
step 1 first.

### Traefik and CrowdSec

`TRAEFIK_MIDDLEWARES` is the router's whole middleware chain, default
`default-no-crowdsec@file` (the framework convention). openGym is a public
login form: on an instance running sksec, set
`TRAEFIK_MIDDLEWARES: "crowdsec-bouncer@file,default@file"` (or
`default@file` when skfenceha has `CROWDSEC_ENABLED`). openGym adds its own
`Access-Control-Allow-Origin` for the phone app: do not add a CORS
middleware (two such headers break the app). `TLS_OPTIONS` defaults to
`intermediate@file`; `none` omits the label (Traefik's default options).

Client addresses: Traefik forwards the caller in `X-Forwarded-For`, but the
`web` nginx overwrites it with its own peer (Traefik's overlay address)
before the API sees it, so the sign-in throttle and the activity log see
the edge, not the user. The per-address part of openGym's throttle (wrong
passwords, invite codes) therefore counts every caller as one address: a
burst of failures from one client pauses that path for everybody for a
while (the per-name throttle is unaffected). Brute force protection at the
edge (CrowdSec) is the one that knows real addresses; `AUDIT_IP` stays
`off`.

### Health checks

`api`: `wget --spider http://127.0.0.1:3000/api/health` (503 when `/data`
is not writable). `web`: `wget --spider http://127.0.0.1:8080/`. Both on
`HEALTH_CHECK_INTERVAL` / `_TIMEOUT` / `_RETRIES` / `_START_PERIOD` (30s,
10s, 3, 30s); the images' own checks only run every 5 minutes. `backup`
has its health check disabled (the image's would probe an api it does not
run). Traefik's service health check is `/api/health`.

### Backups

The `backup` sidecar writes `BACKUP_PATH/skgym-<UTC timestamp>.tar.gz`
(root `0600`, it contains passkeys and the session secret): one archive per
run, written to a temp file, verified (gzip and tar read it back and it holds
`./secret`) and only then renamed; archives older than `BACKUP_KEEP_DAYS`
are pruned only after a good one was written. First archive
`BACKUP_START_DELAY` seconds after the sidecar starts. A manual archive:
`docker exec $(docker ps -qf name=skgym-<env>_backup) /bin/sh /usr/local/bin/skgym-backup once`
on the node running it.

With skbackup on the storage host (tier 2 copy of the app dir plus a
freshness check on the archives):

```yaml
skbackup:
  copy:
    apps:
      - name: skgym-prod
        newest: [{dir: backup, keep: 2}]   # a run may still be writing the newest
        dump: backup                        # warn when no archive is fresher than dumps.max_age_hours
```

Keep `BACKUP_FREQUENCY` at most `skbackup.dumps.max_age_hours` (default 26
hours; the default 86400 s fits). With a local `DATA_PATH` the archives are
the only part skbackup sees: put `BACKUP_PATH` under `/var/data` then (a
local `DATA_PATH` with a shared `BACKUP_PATH` is allowed).

Restore: stop the api (`docker service scale skgym-<env>_api=0`), unpack an
archive into an empty `DATA_PATH`, keep `SESSION_SECRET` in the vault equal
to the archived `secret` (or accept a sign-out), redeploy.

### Upgrades

Bump `API_IMAGE` and `WEB_IMAGE` **together** to the same upstream release
(tag and digest, both images are released in lockstep), read the upstream
CHANGELOG first, take an archive (`skgym-backup once`), then redeploy. The
api migrates its JSON files on boot when a release changes their shape, so
a downgrade is a restore, not an image swap (`probe.yml` marks the app
`schema_changing`). The framework default moves only through a framework
release (digests checked by `v1/scripts/check_images.sh`).

### Resources

Sized for a small homelab node: api limit 0.5 CPU / 384M (reservation 64M;
measured idle well under 100M), web 0.25 CPU / 64M (16M), backup 0.25 CPU /
128M (16M). Knobs: `API_CPUS`, `API_MEMORY_LIMIT`, `API_MEMORY_RESERVATION`,
`WEB_CPUS`, `WEB_MEMORY_LIMIT`, `WEB_MEMORY_RESERVATION`.

## Deployment

```bash
ansible-playbook -i envs/prod/inventory.ini \
  framework/v1/ansible/optional/skgym/deploy_skgym-prod.yml \
  -e target_manager_group=swarm_managers \
  --vault-password-file ~/.vault_pass_env/.<instance>_prod_vault_pass
```

The play: checks the vault (fails on a missing `SESSION_SECRET`, an image
without a digest, a local data path without `DATA_NODE`), creates the
directories, writes the session secret, installs the backup script and the
env/compose files, ensures the networks, deploys stack `skgym-<env>`, and
restarts the api when its env file or the secret changed (bind mounts and
env files do not change the service spec by themselves).

## Configuration (vault)

`skgym:` in `optional/group_vars/<env>/skgym-<env>-<domain dashed>-<cluster>_vault.yml`.

```yaml
skgym:
  SESSION_SECRET: "<openssl rand -hex 32>"   # required, secret, at least 32 characters
  CLUSTERNAME: cluster1                     # default: inventory cluster_name
  DOMAIN: example.com                       # default: inventory domain
  CLOUDFLARED: false                        # true: default host is under DOMAIN, not CLUSTERNAME.DOMAIN
  HOSTNAME: ""                              # public host; default skgym[-dev|-staging].<base domain>
  TRAEFIK_MIDDLEWARES: ""                   # default default-no-crowdsec@file
  SSO_MIDDLEWARE: ""                        # e.g. authentik@file: forward auth on everything but /api/
  TLS_OPTIONS: ""                           # default intermediate@file; "none" = no tls.options label
  INVITE_ONLY: false                        # true after the first admin exists (see "first admin")
  FIRST_USER_ADMIN: true
  ADMIN_UIDS: ""                            # comma-separated openGym user ids
  ALLOW_GUEST: true                         # "Continue without account" (data stays in the browser)
  PASSWORD_LOGIN: false                     # name + password next to passkeys
  RP_NAME: openGym                          # name shown in the passkey prompt
  DEFAULT_LANG: ""                          # e.g. de, pt-BR
  SESSION_DAYS: 90
  AUDIT_LOG: true
  AUDIT_IP: "off"                           # off | net | full (the API sees the edge, see above)
  AUDIT_MAX: 5000                           # 0 = no cap
  AUDIT_DAYS: 90                            # 0 = no cap
  MEDIA_UPLOADS: true                       # photos/videos of custom exercises
  MEDIA_QUOTA_MB: 200                       # per profile, 0 = no cap
  MEDIA_UPLOAD_MAX: 48m                     # nginx cap per upload (keep above the API's 40 MB video cap)
  VAPID_SUBJECT: ""                         # mailto: contact for push services; default ORIGIN
  COACH_DISABLED: true                      # kill switch for the AI Coach
  TZ: UTC
  extra_env: {}                             # any other upstream api variable, verbatim into skgym.env
  API_IMAGE: ""                             # default below; must carry @sha256:
  WEB_IMAGE: ""                             # default below; must carry @sha256:
  WEB_REPLICAS: 1
  DATA_PATH: ""                             # default /var/data/skgym-<env>/data
  BACKUP_PATH: ""                           # default /var/data/skgym-<env>/backup
  DATA_NODE: ""                             # pin api + backup to this node (required with a local path)
  PLACEMENT_CONSTRAINTS: []                 # api + backup, default ["node.role == worker"]
  WEB_PLACEMENT_CONSTRAINTS: []             # web, default ["node.role == worker"]
  HEALTH_CHECK_INTERVAL: 30s
  HEALTH_CHECK_TIMEOUT: 10s
  HEALTH_CHECK_RETRIES: 3
  HEALTH_CHECK_START_PERIOD: 30s
  API_CPUS: "0.50"
  API_MEMORY_LIMIT: 384M
  API_MEMORY_RESERVATION: 64M
  WEB_CPUS: "0.25"
  WEB_MEMORY_LIMIT: 64M
  WEB_MEMORY_RESERVATION: 16M
  BACKUP_ENABLED: true
  BACKUP_FREQUENCY: 86400                   # seconds between archives
  BACKUP_KEEP_DAYS: 7
  BACKUP_START_DELAY: 60                    # seconds before the first archive
```

Default images: `ghcr.io/duartesantos8/opengym-api:1.4.1@sha256:4bc07fe7...`
and `ghcr.io/duartesantos8/opengym-web:1.4.1@sha256:e32cae9d...` (full
digests in the playbooks). Networks: override with the flat per-env
`skgym_<env>_networks` list.

Deliberately not exposed: the upstream `PORT`, `DATA_DIR`, `TRUST_PROXY`
(fixed by this stack's shape), `BASE_PATH` (served at the host root),
`CF_CONNECTING_IP` (empty: a direct client cannot forge the logged address)
and the Coach runtime target. Anything else upstream reads goes through
`extra_env` (for example `MEDIA_GC_GRACE_DAYS`, `MEDIA_VIDEO_MAX_MB`).

## Verification

```bash
docker service ls --filter name=skgym
curl -s https://<host>/api/health      # {"ok":true,"users":N,"writable":true}
ls -l <BACKUP_PATH>                    # skgym-<timestamp>.tar.gz, newest within BACKUP_FREQUENCY
```

Tests: `v1/tests/test_skgym_render.py` (the deploy through real Ansible:
defaults, every knob set, knob-off paths, the missing-secret and
unpinned-image failures) and `v1/tests/test_skgym_backup.py` (the backup
script for real: a good archive, a failed run that keeps the previous one,
retention). The skstack06 harness stage `skgym` deploys it on the lab
cluster and checks convergence, the route through skfenceha, the app and
API through it, persistence across an api restart, and an archive from the
backup sidecar.
