# skmon v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the v1 `optional/skmon` role so a deploy with an empty `EXTRA_*` config gives host, container, swarm, storage, edge and certificate metrics, the curated alert set routed to the estate's `sk-alert`, and provisioned dashboards, with the alert path free of shared storage and storage failures alerted in 60 s or less.

**Architecture:** One Grafana Alloy agent per node, run by a new Ansible play as a host container (or a systemd binary on non-swarm hosts), scraped by single-node VictoriaMetrics on a pinned `DATA_NODE` with local-disk `DATA_PATH`. vmalert evaluates the curated rules, Alertmanager groups and inhibits, and a small Python bridge calls the estate's own pinned `sk-alert`. A purpose-built `skswarm-exporter` supplies Swarm desired-vs-running state. Every alert-path config is a content-hash-named Swarm config, so nothing on that path touches `/var/data`.

**Tech Stack:** Ansible (v1 role, shell-driven `docker` CLI, no collections), Docker Swarm compose v3 templates (Jinja2), Grafana Alloy, VictoriaMetrics + vmalert + vmalert-tool, Prometheus Alertmanager, Loki, Grafana, Pyroscope, Python 3 standard library (bridge, exporter, Authentik provisioner), pytest render tests, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-11-skmon-v2-design.md` (merged as 378081e75). Section numbers below (for example "spec 8.2") refer to it. Read both documents.

## Global Constraints

- Role path: `v1/ansible/optional/skmon`. `v2/compute/skmon` is out of scope (spec 3).
- Traefik labels use `traefik.swarm.*` only; never `traefik.docker.*` (spec 5).
- Images pinned to an exact version released at least 14 days before the build; no floating tags (spec 4, 5, F5).
- Nothing on the alert path (agent, VictoriaMetrics, vmalert, Alertmanager, bridge) reads config from, or writes data to, `/var/data` (spec 4, D13).
- `skmon.replicas: 0` stops every skmon workload on every node, including agents; a later non-zero value brings them back with data intact. `DATA_PATH` is never deleted by parking (spec 5, 14). This must hold after every phase.
- No secrets in argv; secrets go in Docker secrets or env files (spec 5).
- The public framework carries no hostnames, IPs or estate names. Test fixtures use `example.test` / `render.example.test` values only (spec 5).
- No cross-estate data path: no remote write, federation, shared Grafana or cross-estate routing (spec 4). The only crossing is the outside Kuma probe of the bridge's `/healthz` (spec 5, 9.5).
- Every web UI gets an Authentik portal tile with an icon through `shared/tasks/authentik_portal_tile.yml`, access mode `admin-only`, group `skadmin` (spec 5, 10).
- Every alert rule has a `for:` window (except where spec 8 gives `0s` or none), labels `severity` (`critical`|`warning`), `class` (`node`, `storage`, `swarm`, `http`, `capacity`, `container`, `cert`, `meta`), `estate`, and a one-sentence `runbook` annotation (spec 4, 8).
- Defaults: `DATA_PATH` `/srv/local/skmon-<env>`, `METRICS_RETENTION` `90d`, `LOGS_RETENTION` `30d`, `PROFILES_RETENTION` `14d`, `SCRAPE_INTERVAL_FAST` `15s`, `SCRAPE_INTERVAL` `30s`, `AGENT_PORT` `12345`, `D_STATE_THRESHOLD` `10` (spec 7.2, 8, 12, D17, D18).
- Container names: agent `skmon-<env>-alloy`; agent config `/etc/skmon-<env>/alloy/`, state `/var/lib/skmon-<env>/alloy/` (spec 7.2).
- Removed vault keys fail the play with a clear message: every `PROMETHEUS_*`, `NODE_EXPORTER_*`, `CADVISOR_*`, `PROMTAIL_*`, `JAEGER_*` (spec 12).
- The three env plays (`deploy_skmon-{dev,staging,prod}.yml`) stay task-for-task identical (enforced by `v1/tests/test_env_playbook_parity.py`). Every change to one play is made to all three.
- Local runs on the implementer's machine: at most `python3 -m pytest -q <one file>`, never the whole suite and never `-n`. The full suite and the render gate run in CI.
- Commit as soon as a task's targeted test passes; the CI run is verification, not a gate on committing.
- No em or en dashes anywhere (code, comments, docs, commit messages).

## Review Focus

1. **`DATA_PATH` spelled oddly** (`/var/data`, `/var/data/`, `/var/data//skmon`, `/var/data/../var/data/x`, a trailing slash): the guard must reject all of them and must still accept `/var/database/skmon` and `/srv/local/skmon-prod/`. Pinned in Task 2 (`test_data_path_normalization`).
2. **Vault values arriving as strings** (`replicas: "0"`, `PROFILING.enabled: "false"`, `D_STATE_THRESHOLD: "10"`, `PVE.enabled: "no"`): parking and opt-ins must behave as for the typed value. Pinned in Task 3 (`test_replicas_string_zero_parks_everything`) and Task 22 (`test_profiling_string_false_is_off`).
3. **An Alertmanager payload the bridge did not expect** (no `node`/`instance` label, 200 alerts in one group, a non-ASCII summary, `sk-alert` hanging): the bridge must post one message with a fallback title, cap the body, and return 500 after a timeout instead of blocking Alertmanager. Pinned in Task 12 (`test_title_fallback_chain`, `test_body_capped`, `test_skalert_timeout_returns_500`).
4. **The Docker API failing or hanging under the exporter** (the exact condition of the reference incident): the exporter must set `skswarm_up 0`, record the call's duration, keep the last known desired/running values (so `ServiceBelowReplicas` does not resolve spuriously) and keep serving `/metrics`. Pinned in Task 15 (`test_api_failure_keeps_last_values_and_sets_up_zero`).
5. **`DATA_NODE` that is not a swarm node** (typo, a removed node): every stateful service would sit in `Pending` forever while the deploy waits. The play must fail before deploying, naming the known nodes. Pinned in Task 2 (`test_data_node_must_be_a_swarm_node`).

### Spec-gap decisions made by this plan

These are choices the spec leaves open. Each is pinned by a test in the named task.

- **B2** bridge base image: pinned upstream `python:3.13-bookworm` (Debian full: `bash`, `curl`, `python3` present). Exporter base: pinned `python:3.13-slim-bookworm`. Socket proxy: the `tecnativa/docker-socket-proxy` line skfence already uses, digest-pinned (Tasks 4, 13, 16).
- **B3** both helpers are single-file stdlib Python delivered as Swarm configs (Tasks 12, 15).
- **B4** the agent binds `AGENT_LISTEN_ADDR` only; Loki, Pyroscope and `/healthz` host-mode ports get an iptables allowlist in `DOCKER-USER` (and `INPUT` for the systemd agent) built from the inventory addresses of `skmon_agent_hosts`, plus `HEALTHZ_ALLOW` for the outside probe (Task 8).
- **B5** the ZFS dashboard is built here (Task 19).
- **B6** Swarm configs are hash-named by the compose template itself: `name: skmon_<env>_<key>_<first 12 hex of sha256 of content>` (Task 3).
- **B7** skbackup coverage: not in this plan; the README names `DATA_PATH/grafana` and `DATA_PATH/alertmanager` as the paths worth backing up (Task 24).
- **B9** default scrapes beyond Traefik: none. The `apps` dashboards stay and render only when an estate adds scrapes through `EXTRA_SCRAPE_CONFIGS` (Task 18).
- Global service desired count: tasks with `DesiredState == running`, the same rule `docker service ls` uses for global mode (Task 15).
- Muted-count line in messages (spec 9.3): the bridge reads `GET /api/v2/alerts?active=false&silenced=false&inhibited=true` from Alertmanager and omits the line if the call fails (Task 12).
- `MonitorDiskFilling` mountpoint: the play resolves it with `findmnt -n -o TARGET -T <DATA_PATH>` on `DATA_NODE` and renders it into the rule (Task 10).
- Grafana and forward-auth client secrets: operator-generated into the vault (`openssl rand -hex 32`), asserted 32+ characters, pushed to Authentik by the provisioner, never printed. Same as skrac (Task 20).
- Dashboard provenance lives in `dashboards/SOURCES.yml` (JSON has no comments) (Task 18).
