# AGENTS.md (skstacks)

The SKStacks infrastructure framework: Ansible roles and playbooks for Docker Swarm (v1, what
production instances run) and the multi-platform v2 deployment engine. Overview:
[README.md](./README.md). v1: [v1/README.md](./v1/README.md) and the
[v1 service catalog](./docs/v1-service-catalog.md). v2: [v2/README.md](./v2/README.md) and
[v2/AGENTS.md](./v2/AGENTS.md). This file follows
[AGENT_INSTRUCTIONS_STANDARD](https://github.com/smilinTux/sk-standards/blob/main/standards/AGENT_INSTRUCTIONS_STANDARD.md).
There is no `CLAUDE.md`: Claude Code reads this file, and a `CLAUDE.md` next to it would hide it.
It applies to every agent (Claude Code, Codex, Pi, Hermes and others).

## Source of truth and invariants

- **This repo is the framework, never an instance.** Site values (inventory, real vaults, which
  optional services run) live in each operator's private instance repo, which pins this repo as a
  `framework/` submodule at a released tag (`skstacks-vMAJOR.MINOR.PATCH`). See
  [v2/docs/INSTANCE-MODEL.md](./v2/docs/INSTANCE-MODEL.md).
- **`templates/config-repo/` is the single source** of the public `skstacks-config-template` repo,
  generated by `scripts/generate-config-template.sh`. The `config-template-drift` workflow fails when
  the two drift; it only detects, it never publishes.
- **No ansible-vault ciphertext anywhere in the tree.** The skred gate fails closed on the
  `$ANSIBLE_VAULT` header.
- **Every image is pinned** (tag or digest, never `:latest`); the framework tests enforce it.

## Commands

CI runs these (`.github/workflows/framework-tests.yml`, `v2-tests.yml`, `config-template-drift.yml`,
`skred-scan.yml`), all on Python 3.12.

```bash
pip install pytest pyyaml ansible jsonschema
python -m pytest -q v1/tests v2/platform/swarm/tests v2/platform/k3d/tests   # framework tests (needs restic)
python v1/tests/render/render_playbooks.py                                     # render gate (ansible-core==2.21.3)
python -m pytest -q tools                                                      # skstacks-deploy tool
(cd v2/infra/tofu/modules/libvirt-cluster && tofu init -backend=false && tofu test)
tofu fmt -check -recursive v2/infra/tofu/modules/libvirt-cluster v2/infra/tofu/examples/libvirt-swarm
(cd v2 && for p in skwire skred skrender skbloom; do python -m pytest $p/tests -q; done)
python -m pytest -q scripts/tests/test_config_template_tooling.py             # config template tooling
scripts/scrub-check.sh templates/config-repo                                   # no real IPs in the template
(cd v2 && PYTHONPATH=. python -m skred.cli gate . --fail-on high)              # skred gate (gitleaks, trivy, semgrep)
```

What the gates cover: [docs/testing.md](./docs/testing.md).

## Rules

- **Writing style:** no em dashes (U+2014) and no en dashes (U+2013) anywhere: code, comments,
  docs, commits, PR bodies. Use commas, parentheses, colons or a new sentence. Hyphens are fine.
- **Branch and commit:** never commit to `main`. Branch, commit and push as soon as a fast check
  passes and before any long suite, then open a PR. Never end a turn waiting on a background job
  with uncommitted work.
- **Release lines:** a PR's base branch MUST be the release line it targets. If the PR title or plan
  says `[target vX.Y.Z]`, the base is `integration/vX.Y.Z`; if that branch does not exist yet, leave
  the PR open and retarget later. Never merge into a different line than the stated target. A
  `release/vX.Y.Z` branch PRs into `main`.
- **Releases:** cut only after a full end-to-end harness run passes for the release pin. A failed
  stage may be resumed only when it then passes with no code change (a glitch); otherwise fix it and
  rerun in full.
- **Tests first:** pytest under `v1/tests`, render gate under `v1/tests/render`; at least happy
  path, edge case and failure per behavior. Never skip, weaken or delete an assertion to get a pass.
- **CHANGELOG:** every behavior change gets a bullet under the target release in
  [CHANGELOG.md](./CHANGELOG.md), saying what an instance must do (`**Instance action**: ...`).
- **Attribution:** a `Co-Authored-By` trailer names the agent that actually did the work, or is
  left out. Never one you cannot evidence.
- **Generated files:** the published config template is generated from `templates/config-repo/`
  by `scripts/generate-config-template.sh`; edit the source, never the generated copy.

## Privacy

This repo is public. Never add site hostnames, domains, private or tailnet IPs, home-directory
paths, people's names or machines, estate names, or live site config. Use placeholders
(`example.com`, `site-a`, `192.0.2.x`). Check compound tokens too: a site name inside a longer
identifier is still a leak. Never commit secrets or ansible-vault ciphertext; read secrets by
single-key extraction and never print them. Enforced by `skred-scan.yml` (gitleaks, trivy,
semgrep, and an estate denylist gate fed from a private secret) and `scripts/scrub-check.sh` for
the config template.

## Hazards

- **v1 vs v2:** a service running on real iron today is v1. v2 is not yet hosting production;
  do not mix v2 patterns into v1 roles. v3 is a placeholder; see [v3/AGENTS.md](./v3/AGENTS.md).
- **Template drift:** editing `templates/config-repo/` without republishing the template repo turns
  `config-template-drift` red until someone regenerates and pushes the template repo by hand.
- **Concurrent sessions:** other agents often work this repo at the same time. Branch from a fresh
  `origin/main`, keep PRs small, and never leave edits uncommitted across turns.
